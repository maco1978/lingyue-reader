# 聆阅看书（Lingyue Reader）第一版设计规格

- 日期：2026-11-26
- 状态：设计已确认，待用户审阅后进入实施计划
- 作者：用户体验研究员（UX Researcher）

## 1. 项目定位

### 一句话

一款开源的「看书软件 + 读书搭子 Agent」：支持主流电子书格式，能看能听，听书用 MOSS-TTS 匹配音色，并有一个懂你在读什么的 AI 陪你聊书。做成一个产品系列，第一版服务成人小说读者，绘本书讲给小朋友的功能排在后续产品。

### 差异化依据

起点、番茄等产品的优势是版权书库，本产品不与之竞争内容，而是竞争**阅读体验与 AI 伴读**：

- 书级状态贯通：阅读进度、划线、听书位置、聊天历史都属于同一本书，跨界面不丢上下文。
- 真正懂书的搭子：不是通用聊天框，而是带着「读到哪、划过哪、聊过什么」的上下文。
- 开源、可插拔、数据本地：用户自带 API Key，不绑定厂商。

### 核心假设（待验证）

> 成人小说读者愿意边看书边跟 AI 聊书。

这是整个差异化的赌注，不直接当成事实。第 9 节给出验证计划；若被证伪，第一版把搭子降级为入口而非主路径。

## 2. 范围

### 第一版做

- 主流格式导入：EPUB、PDF（文字版）、MOBI、AZW3、TXT、FB2、DOCX、RTF、HTML；CBZ 作为图片式预留。
- 阅读：分页/滚动、字号/行高/字距、日夜模式、目录跳转、划线与笔记（锚点定位）。
- 听书：MOSS-TTS 托管 API，流式播放，音色卡（参考音频 + 语速 + 情绪）。
- 读书搭子：4 项能力（见第 6 节），书级记忆，可插拔 LLM。
- 开源底座：复用 dsh-Reading 类 GPL-3.0 项目；整体开源。

### 第一版不做（YAGNI）

- 绘本模式（独立后续产品）。
- 书源搜书、书城、版权内容分发。
- 多端云同步（WebDAV 留接口）。
- 读书报告、人物关系图、跨书知识库。
- 社区分享。

## 3. 用户与场景

主要用户：成人小说读者，常见场景为通勤与睡前，习惯用手机或平板看小说，希望「听」作为「看」的替代或补充，并愿意就书内容与人（或 AI）讨论。

关键旅程：导入书 → 书架看到进度 → 阅读 → 切到听书接着听 → 对某段话问搭子 → 搭子定位原文并朗读。

## 4. 架构：六层

每层只做一件事，层间用明确接口通信。关键是第 4 层与第 5 层，它们承载未来的绘本模式与 Nano 引擎扩展位。

| 层 | 名称 | 职责 | 扩展位 |
|----|------|------|--------|
| ⑥ | 应用壳 | 书架 / 阅读 / 播放器 / 搭子四个界面，共享当前书与书级状态 | 绘本 UI 作为新界面接入 |
| ⑤ | 读书搭子 Agent | LLM + 书级记忆 + 工具（定位原文→跳转/朗读） | 报告、关系图等后续能力 |
| ④ | 听书引擎层 | 统一 `TTSEngine` 接口，MOSS API 第一版 | Nano / 旗舰模型作为新适配器 |
| ③ | 阅读渲染 | 分页/滚动、排版、划线笔记（锚点定位） | 无 |
| ② | 格式归一化 | 识别格式，输出统一的 spine + 章节 + 锚点 | CBZ 固定布局供绘本复用 |
| ① | 本地书库 | 原文件 + 元数据 + 进度 + 划线 + 音色卡 + 聊天史，JSON/JSONL | WebDAV 同步 |

切分理由：

- 换引擎不动上层：从 API 换 Nano，只改第 4 层一个适配器。
- 加绘不动主干：绘本 = 第 2 层 CBZ 固定布局 + 第 4 层音色卡 + 新绘本界面，其余复用。
- 搭子不是普通聊天框：天生带书的上下文。
- 数据在本地：符合开源定位，也便于后续加同步。

## 5. 格式归一化

导入层做「格式归一化」：不论输入格式，统一转成同一套书模型（spine + 章节 + 锚点），上层阅读/听书/搭子完全不分叉。

| 类别 | 格式 | 呈现 |
|------|------|------|
| 原样渲染 | EPUB、PDF（文字版） | 保留插图与版式（PDF 有限） |
| 重排为文字章节 | MOBI、AZW3、TXT、FB2、DOCX、RTF、HTML | 无插图、无原始版式 |
| 图片式（预留） | CBZ、CBR | 固定布局，供绘本模式复用 |

实现复用：foliate-js 原生支持 EPUB / MOBI / KF8(AZW3) / FB2 / CBZ / PDF（实验性），配合现成转换库覆盖 DOCX / RTF / HTML；或直接复用 dsh-Reading 已有格式层。

用户体验约定：

- 书架卡片标注「原版」或「重排」，提前说明重排书会丢插图和版式。
- DRM 加密书明确拒绝，给出人话提示，不做破解。

锚点用 EPUB CFI（结构化位置）而非百分比或字符偏移，改字号、换设备都不漂。

## 6. 读书搭子 Agent

### 能力边界（第一版只做前 4 条）

1. 聊情节：解释伏笔、梳理人物关系。
2. 助手工具：定位原文 → 跳转阅读页 / 直接朗读该段。
3. 章节总结：回顾上一章（基于当前章节片段）。
4. 划线问答：对划线句子问出处、典故。

后续版本：读书报告、人物关系图、跨书知识库。

### 书级记忆

- 自动带入：当前章节及前后各一段、最近 20 条划线、最近 10 轮对话摘要。
- 不塞全文：需要更大范围时用检索工具按需取，不占用上下文。
- 存本地：聊天史为 JSONL，随书备份，不上传第三方。

### 可验证性与伦理

- 回答标注「AI 生成」。
- 涉及情节结论时提供「原文出处」按钮，读者可核对；可验证性直接决定信任度。

## 7. 听书引擎与音色卡

### 引擎

- 统一 `TTSEngine` 接口。
- 第一版：MOSS-TTS 托管 API（MOSI 官方 API），流式生成、边生成边播。
- 手机端可用性结论（2026-11-26 查证）：Nano 官方仅有 Android ONNX Runtime 的 smoke 示例，无官方 iOS 示例（社区有 Core ML / ONNX / speech-swift 项目）；官方 Nano Reader 是桌面浏览器扩展，手机浏览器不可用。故第一版不把本地 Nano 作为核心路线，仅留适配器接口，后续 Android 先行。

### 音色卡（听书与绘本共用资产）

| 字段 | 说明 |
|------|------|
| 名称 | 音色标识 |
| 参考音频 | 几秒即可，存本地书库 |
| 语速 | 数值参数 |
| 情绪/风格标签 | 用于配音表现 |

- 第一版：一张卡 = 全书一个旁白声音。
- 绘本阶段：一个故事多张卡 = 旁白 + 各角色，脚本标角色名自动分配音色。
- 换 TTS 引擎时音色卡不受影响。

## 8. LLM 选型：可插拔

- 当前主用：腾讯混元 Hy4 Flash（便宜，中文强，100 万 token 上下文）。
- 辅用：DeepSeek（便宜，工具调用稳）。
- 可插拔：用户自填 API Key，接口留好，任何人可换 Mimo / 本地开源模型，不绑定厂商。

说明：搭子不需要把整本书塞进上下文，只带当前章节片段 + 划线 + 对话摘要，故普通长上下文模型即可，成本可控。

## 9. 容错、无障碍与验证计划

### 容错：三层降级

- LLM 挂了：自动切备用模型（Hy4 ↔ DeepSeek），都失败则回缓存回答并明确提示。
- TTS 失败：保留已生成音频，断点续听，不从头来；可切引擎。
- 格式导入失败：人话错误码（如「这本书是加密的，读不了」），不静默。
- API Key 缺失：首次引导填 Key；本地阅读离线可用，不被阻断。

### 无障碍（默认要求）

- 视障：屏幕阅读器可遍历书架与目录；听书本身是无障碍红利。
- 阅读障碍/老年：字号无级缩放、行高、字距、可选衬线/黑体、高对比度。
- 听障：听书配同步文字高亮（听读同步）。
- 动效敏感：尊重系统「减少动态效果」。
- 键盘/手柄：全键盘导航，焦点可见。

### 验证计划（先证伪核心假设）

- 方法：8 位小说读者深访 + 可用性测试（看 / 听 / 问搭子三条任务），任务完成率 + SUS 量表 + 半结构化访谈。
- 成功标准：≥ 70% 用户主动用过搭子且评分 ≥ 4/5；若多数人「只用看和听」，则把搭子降级为入口而非主路径。
- 伦理：知情同意、数据本地、录音脱敏、可随时退出。

## 10. 成功指标

### 定量

- 格式导入成功率 ≥ 95%（常见无 DRM 书）。
- 听书首字延迟与断点续听可用性达标。
- 搭子主动使用率 ≥ 70%，满意度 ≥ 4/5。

### 定性

- 用户能说清「搭子与番茄/起点聊天功能的区别」。
- 可用性测试中无因「书级状态丢失」导致的困惑。
